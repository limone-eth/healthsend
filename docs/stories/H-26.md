# H-26 — The landing page breaks the one d/m rule, and nobody wrote it down

## Story
- `DESIGN.md` states that desktop and mobile carry identical content and copy, and names 4.2m as
  the **only** sanctioned divergence: *"Any other d/m difference is a bug, not a decision."* The
  landing page has eight of them.

## Context
Found while folding H-20 (2026-09-12), by diffing the text of `xKspH` against `t659K4` rather than
by reading either one.

Mobile abridges eight strings and **omits two desktop strings entirely**:

| Desktop | Mobile |
|---|---|
| "It still has your panel. There was never a moment where that access was supposed to end, so it did not." | "It still has your panel. Nobody built a moment where that access ends." |
| "Keeps a PDF of your bloods in her inbox long after the twelve weeks are over. Not out of malice — nobody built her a way to give it back." | "Keeps a PDF of your bloods long after the twelve weeks are over." |
| "Drop in an export from your watch and a lab result. Your name and date of birth are set aside as they come in…" | "Drop in an export and a lab result. Your name is set aside as it comes in." |
| "See what a recipient gets" | *(absent)* |
| "Signing in takes one tap and creates nothing we can read." | *(absent)* |

…and three more in the same shape.

**These read as edited, not drifted.** Each one is a tighter sentence carrying the same claim, which
is what good mobile marketing copy looks like. So the likely truth is that the rule was written for
product screens and the landing page is an exception nobody recorded — not that the frame is wrong.

But it has to be one or the other, and right now the written rule says the canvas is buggy while
the canvas says the rule is incomplete. That ambiguity already cost something concrete: the H-20
brief asserted the rule, the worker followed the canvas instead, and it was right to.

**Two things to be careful about if the exception is granted.** The abridgement drops *"and date of
birth"* from the de-identification promise, and drops *"creates nothing we can read"* from sign-in.
Both are claims about what the product does with personal data, and a mobile reader gets a weaker
version of the first and none of the second. Shortening prose is fine; shortening a promise is a
different thing, and the exception should say so.

## Decision needed
Either:
1. **Grant the exception** — amend `DESIGN.md` § Screen inventory so the landing page joins 4.2m as
   a sanctioned divergence, state why (persuade surface, not a product screen), and add the
   constraint that abridgement may not weaken a claim about personal data; or
2. **Re-sync the frame** — bring `t659K4`'s copy back to `xKspH`'s and update `app/landing/page.tsx`
   to render one set of strings at both widths.

The built page already implements option 1's behaviour, so choosing 2 means a code change as well
as a canvas change.
