# H-34 — Tests that pass without testing
## Story
- Six tests do not test what they are named for. One of them would pass while the storage it covers
  wrote to the wrong key entirely.

## Context
From the adversarial review, which was asked to attack the tests as hard as the code because this
repository has previously shipped a `PASS` that asserted only that some buffers were non-empty.

- **`scripts/access-log-proof.mjs:101` — the read test does not read what the write test wrote.**
  The write test stores events in `recorded`; the read test builds an unrelated `opened` array at
  line 105 and returns it at 106. A writer that stored the wrong key, overwrote entries, or wrote
  nothing would still pass. This is the vacuous-test class, found again.
- **`scripts/revoke-proof.mjs` does not independently test entity binding** — that a signature for
  one entity key cannot end another. That property is the reason the key is in the message.
- **The offline network guard does not prove the lane is offline.** Route abort is not an
  assertion, and the helper allows every same-origin route rather than only page assets and the
  mocked holder.
- **Route stubs accept wrong request values**, so a caller sending the wrong body still passes.
- **The multi-document test never opens the second document.**
- **Expiry while a document is open is untested** — the countdown closing the page under a reader
  is a product behaviour with a comment explaining why it matters.

## What to build
Fix each so it fails when the named behaviour breaks. For each one, demonstrate the failure first —
break the code, watch the test go red, restore it — and record that in the story's Choices ledger.
A test that has never been seen to fail is a claim, not a check.
