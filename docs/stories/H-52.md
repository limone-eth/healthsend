# H-52 — The TACo adapter, behind an availability gate

## Story
- Implement `KeyReleaseProvider` with real TACo, and make the absence of a working network a
  first-class, honest outcome rather than a crash or a fake pass.

## Context
Task 3 of the TACo PoC plan. Depends on H-50's provider interface.

**Pin `@nucypher/taco` to 0.6.0 and `ethers` to 5.7.2.** The current TACo quick reference requires
ethers v5. Do not float either.

Browser-only. Node proof scripts must not pull the adapter in.

## What to build
`lib/key-release/taco.ts`: initialization, the Arkiv `arkiv_query` condition from H-51's binding,
encryption, and release.

**Failing closed is the feature.** Arkiv unavailable, TACo unavailable, a malformed response, or
any uncertainty about current state must release nothing and surface as *retryable
unavailability* — never as expiry. The product already draws that distinction sharply (3.3 stays
in light chrome precisely so it never reads as an ending); this must land on the same side of it.

## Evidence
An opt-in live probe against a real cohort and a disposable Arkiv entity. **The report must say
which of two things happened:** a real multi-node result, or an infrastructure block. A green run
that never reached a node proves nothing, and this repository has already shipped six tests that
passed without testing anything (H-34).

## Non-goals
- Self-hosting a cohort, DKG contracts or Porter.
- Replacing or deleting the Redis holder. It stays until this passes on a supported network.
