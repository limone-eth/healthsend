# H-65 — Lit Chipotle as the key-release provider, because it works today

## Story
- Release the held half of a share's key through Lit Chipotle, which has a live network today, behind
  the same provider interface TACo uses — so the product can demonstrate a real network refusing after
  the deadline, not just an offline proof.

## Operator decision, 2026-09-12
**Use Lit Chipotle because it works today. Keep TACo built, but park that code.** TACo's live probe
(H-52) is blocked at Porter — `porter-lynx.nucypher.io` does not resolve — and TACo's own docs say there
is no operating network until a planned relaunch. The TACo adapter stays in `lib/key-release/taco.ts`,
unwired; H-54 and H-55 are parked.

## The trust model, stated honestly — this is not a threshold committee
Chipotle derives its encryption key from a PKP **inside a TEE**. The research is explicit: describe it as
*"a programmable enclave service rather than automatically as an independent threshold committee."*
Moving to it swaps one trusted party (our Redis holder) for another (Lit's enclave hardware, attestation,
and Lit as operator). Every piece of copy, README, and evidence produced by this story must say that.
Never call it decentralised, trustless, or a threshold network.

Research: `~/Desktop/threshold-expiry-alternatives.md` § *Lit: separate the products and trust models*.
Lit docs: encryption models `developer.litprotocol.com/lit-actions/migration/encryption`, secrets
`/lit-actions/secrets`, usage keys `/management/api_keys`, pricing `/management/pricing`, endpoints
`/management/crypto`.

## What to build
- **`lib/key-release/chipotle.ts`** implementing H-50's `KeyReleaseProvider`
  (`lib/key-release/types.ts`). Do not change the interface.
- **An immutable Lit Action** that, on each release request, queries Arkiv's current state and returns
  the held share only while the grant is live. Reuse H-51's condition logic (`buildArkivGrantQuery`):
  native `entity.owner` and `entity.expiresAt` authoritative, deadline capped in the policy, current
  state only — never `atBlock`.
- **Bind everything, because Chipotle's failure modes are different from TACo's:**
  - A shared action that accepts arbitrary ciphertext plus an independently supplied live `grantId` is
    **insufficient** — a caller would substitute a live grant for an expired one. Bind grant identity,
    ciphertext, expected owner, and capability commitment inside the authenticated envelope (H-50's
    `grant-package.ts` binding).
  - **Only one action may use the PKP.** A second, more permissive decrypt action allowed on the same PKP
    bypasses the gate entirely. The adapter must refuse to operate if it cannot confirm that.
- **Walletless recipients** via a restricted usage API key scoped to this group. The master account key
  must never ship to a browser and never be committed.
- **Fail closed.** Chipotle unreachable, credits exhausted, a malformed response, Arkiv unreachable, or any
  uncertainty releases nothing and surfaces as retryable *unavailable*, never as expiry.

## Evidence
- **Live probe first**, like H-52's: `scripts/chipotle-live-probe.mjs`, opt-in, non-destructive, staged —
  endpoint resolves, endpoint answers, action invocable, a release against a fabricated non-existent grant
  is **refused**. Record the outcome in `arkiv/evidence/chipotle-adapter-poc.md` as AVAILABLE or BLOCKED
  with the stage. **Distinguish a network failure from a genuine refusal**, exactly as H-52 did.
- **Offline proof** with an injected fake client, demonstrated red first: binding refuses a substituted
  grant, an expired grant releases nothing, a second permissive action is detected, nothing persists.

## Credentials — operator action may be needed
Chipotle needs an account, usage keys, and service credits. **A worker cannot create accounts or enter
credentials.** If the live probe needs a key, stop at that stage, record it as
`BLOCKED at "credentials"`, and list exactly what the operator must create and which environment
variable names the code reads. Build and prove everything else offline.

## Non-goals
- Wiring Chipotle as the active provider in the send and open path — that follows H-53's asset/grant
  split, as a separate story.
- Deleting or modifying the TACo adapter. It is parked, not removed.
