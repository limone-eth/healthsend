# H-31 — End access now and the access log exist, and are unreachable
## Story
- `endSend` is exported and imported by nothing. The access-log API is read by no component. Two
  stories shipped a capability each and neither is reachable from the product.

## Context
From the adversarial review, two findings rated high at confidence 100.

A repository search for `endSend` finds only its definition at `lib/sends.ts:283`. A search for
access-log reads finds only the route, the library and the proof.

This is honest scoping rather than a defect — H-11 and H-12 were deliberately dispatched as backend
slices while the design kit was still being built in another worktree, and both said so. But the
board should not be able to reach a state where the capability is "done" and the user cannot use
it, which is what happened.

## What to build
The confirm sheet and the log surface, inside 2.6 *Your shares* (`hCcwO` / `aOxXo`), which is H-10.
Either fold this into H-10 or land it first; do not build a second shares screen.

`DESIGN.md` § Words we use: the control says **End access now**, never "Revoke". The log surface is
**"When she looked"**, never "audit trail". `$error` belongs to the end control and nothing else on
the screen.

Note H-29 first: if revocation is reversible, a confirm sheet that promises *"She lost access the
moment you tapped it"* is making a claim the backend does not yet keep.
