# H-66 — Your archive becomes a list of your blood test PDFs

## Story
- Your archive stops being five groups of mostly-empty cards. It is the list of blood test PDFs you have
  added, with one clear action to add more.

## Design
Operator request, 2026-09-12: *"focus only on Blood Tests upload, and listing."*
- **Desktop:** `M2g5J2` — *2.1d Your archive · Blood tests (PDF) · desktop*
- **Mobile:** `W1yi5` — *2.1m Your archive · Blood tests (PDF) · mobile*

Both are copies of the original `ACUf3` / `zsDfc`, which are kept unchanged beside them. Read the nodes
with the pencil MCP (read only); copy strings verbatim from `content` fields, desktop and mobile read
separately.

## What changes, frame to build
- **Header:** title stays *Your archive* (it matches the rail). Lede becomes *"Your blood test PDFs,
  exactly as the lab sent them. Nothing leaves this page unless you share it."* (mobile: *"Your blood
  test PDFs, as the lab sent them."*). Primary action becomes **Add blood tests**, routing to Add, which
  after H-63 takes one or several PDFs in one pick.
- **Removed:** the *Right now* focus card, and the five-group bucket grid (Blood panels, Wearables,
  Medications, Notes, Identity).
- **Eyebrow** counts what is there: *"3 BLOOD TESTS · PDF"* — the number is the real count.
- **The list:** one row per archived PDF — PDF glyph, display name, *"PDF · size · added date"*, and a
  share-status pill. Desktop is one card with divided rows and a final *"Add blood tests — pick one or
  several PDFs"* row; mobile is stacked 62 px rows.
- **Share-status pill — only when it is true.** *"In N shares"* requires knowing which documents went
  into which shares. If the build cannot derive that (H-64 decides whether sends record document ids),
  **omit the pill** rather than render *"Not shared"* on a document that may be in a live share.
- **Empty state:** no PDFs yet → say so and offer **Add blood tests**. Not five empty cards.
- **The identity note is replaced by an honest one.** The old *"Identity — Your name and date of birth
  were separated… no share has ever included them, and none can"* is false for PDFs, which the operator
  chose to share as issued. New desktop copy: *"Shared as issued — Each PDF is shared exactly as your lab
  sent it — including your name and date of birth, if they are printed on it."* Mobile: *"Shared as
  issued — Any name or date of birth on the PDF goes with it."* This screen owns that correction; H-64
  handles the share screen's own wording.

## Evidence
Browser, both widths: add two PDFs (via H-63's Add), **reload**, see both rows with correct name, size and
date; an empty archive shows the empty state; the eyebrow count matches the rows. No personal name
anywhere. A test that inspects component state is not evidence.

## Non-goals
- Wearables, medications, notes and questionnaire screens — out of the PDF focus.
- Sharing (H-64) and removing (H-18, paused).
