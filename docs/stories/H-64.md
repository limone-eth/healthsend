# H-64 — Share one or more archived PDFs in one link

## Story
- Open New share, tick one or more PDFs already in your archive, set a deadline, get one link. The person
  opening it sees the actual PDFs.

## Depends on
H-60 (compose layout) and H-63 (the archive holds PDFs). The combined story `docs/stories/H-62.md`
carries the **Operator decisions** and the **consequence that must be said**; both apply here and the
copy corrections land in this half, because they only become true once PDFs are actually sent as PDFs.

## What to build
- **New share lists archived PDFs with multi-select** — *"Blood test, March and Thyroid panel, June — 2
  of your 12 documents"*. Empty archive says so and routes to Add.
- **A send path from selections:** read the chosen documents with the archive key, pack them into the
  existing multi-document envelope, seal under a **fresh share key**, upload that one sealed bundle,
  split the share key, write the grant. The archive key is never split or sent. **No source PDF is
  uploaded at share time** — assert exactly one upload per share, the sealed bundle.
- **Recipient:** the existing multi-document switcher renders each PDF via `PdfPreview`, with the
  `application/pdf` pinning and `%PDF-` check intact.
- **Say the consequence** on the share screen before the link is created, and correct every claim that
  identifiers are removed (landing STEPS[0], the demo notice, DESIGN, README — the archive's identity note
  moved to H-66, which owns that screen):
  *the document is shared as issued, including any name or date of birth printed on it.*

## Evidence
In a browser with a reload in the middle: share one archived PDF, open the link in a clean context, see it
render; share the other to a second link and show neither source was uploaded again.
