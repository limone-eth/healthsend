# H-27 — Dark mode is broken: 27 of 32 tokens never flip

## Story
- In dark mode every call to action on the landing page is a black rectangle with an invisible
  label. The only surface in this product whose job is to persuade cannot be read by anyone whose
  OS is set to dark.

## Context
Found while folding H-3 (2026-09-12), by opening `/chrome-preview` in a browser that happened to be
in dark mode. No test would have caught it: lint, build, tsc and all five proof lanes pass.

**The mechanism, exactly.** `app/globals.css` defines **32 colour tokens**. The
`prefers-color-scheme: dark` block overrides **5** — and they are the five ad-hoc ones that existed
before H-1, not the design-system tokens H-1 introduced. So in dark mode the palette is half
flipped:

```
--color-surface   #FFFFFF → #1a1816   (in the dark block)
--color-ink       #15161A → #15161A   (not in the dark block)
```

and `components/ui.tsx:44` is:

```
primary: "h-13 rounded-control bg-ink px-6 text-title text-surface"
```

Near-black background, near-black text. Invisible.

The same collision hits every component built on the kit. Affected files, all of them new today:
`components/ui.tsx`, `components/chrome.tsx`, `app/landing/page.tsx`, `app/chrome-preview/page.tsx`,
`app/kitchen-sink/page.tsx` (the last is masked only because H-1 scoped it to forced-light).

**Why the existing pages look fine.** `app/page.tsx` and `app/s/[key]/page.tsx` still use the five
legacy tokens, which do flip. So dark mode appears to work right up until you open anything built
after H-1 — which is now most of the product.

## What to build
Give every token a dark value, or deliberately decide it has none and say so in a comment.

`DESIGN.md`'s frontmatter defines one palette. A second, dark palette is a **design decision**, not
a mechanical inversion: naively inverting produces mud, and `$navy`, `$sage`, `$chalk`, `$umber`
and `$sand` carry meaning that has to survive on a dark ground. `healthsend.pen` Sheet 1 —
Foundations (`gSR4g`) and its Colour roles section (`MwHKE`) are where the roles are defined; read
them before choosing values.

Two structural rules worth following, because they are what went wrong here:
- **Every token gets its complete light definition on bare `:root`**, and the dark block redefines
  only values — never introduces a colour that exists nowhere else.
- **A component takes its foreground and its background from the same token set.** `bg-ink` with
  `text-surface` pairs a token that flips against one that does not, which is the bug.

## The other half of this
Nothing tests it. `pnpm test`'s browser lane runs in the default (light) scheme, so this class of
defect ships silently. Add a dark-mode pass: Playwright supports `colorScheme: "dark"` per project,
so the offline recipient specs and a contrast check over the kit can run twice. A regression here
should fail a command, not wait for someone to open the right page on the right machine.
