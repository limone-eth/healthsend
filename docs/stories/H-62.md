# H-62 — Share from your archive, not from a file you pick

## Story
- You upload a document once. Any day later you open New share, tick one or more documents already in
  your archive, set a deadline, and get a link. No file picker, no re-upload of the source.

## Context
This is the gap between the operator's diagram on the Decode board (*"The whole thing, plainly"*) and
the build, and the code half of `DESIGN.md` § *Upload once, bundle per share*.

What exists today:

- **H-44** persists an encrypted archive on Swarm, keyed from the passkey
  (`deriveAppSecret("healthsend/archive/v1")`), so it reopens on any device.
  `lib/archive-store.ts` exposes `loadMyArchive`, `addRecordsToMyArchive` and
  `scopeMyArchive(selections)`.
- **H-36** made de-identification and scoping run on the send path — but on a **throwaway archive
  built per send** from `File`s picked in that session. Its own comment defers the persisted archive
  to "once a compose flow can select records rather than whole files".
- `createSend({ files: File[], ... })` still takes files.

So `scopeMyArchive` has no production caller, and "upload once, share many times" exists only as a
drawing.

## What to build
- **New share lists what is already in your archive** (from `loadMyArchive`) as selectable items.
  Selecting **one or more documents** is the core interaction — the operator's example is
  *"Blood test, March and Thyroid panel, June — 2 of your 12 documents"*.
- **A send built from archive selections.** Add a path that takes `ArchiveSelection[]`, calls
  `scopeMyArchive`, and seals that scoped payload under a **fresh share key** exactly as the existing
  path seals an envelope — then splits that key, writes the grant, same as today. The archive key is
  never split, never sent, never leaves the device.
- **No new upload of the source document.** The only upload per share is the small sealed slice.
  Assert it: a share from the archive must not call the archive write, and must upload exactly one
  blob — the slice.
- **One link carries all selected documents**, one deadline for the bundle. The recipient screen
  already renders a multi-document switcher (H-5); it must work unchanged.
- **Empty archive:** New share says so and routes to Add, rather than rendering an empty picker.
- **Keep the file path working** for now — adding a new document from New share may still upload it
  into the archive first. Do not remove `createSend`'s file path in this story; route new files into
  the archive and then share from it, or leave the path and say so in `## Choices`.

## Evidence
End to end, in a browser, with reload in the middle: add two documents, **reload**, open New share,
tick one, create the link, open the link in a clean context, see only that document. Then share the
*other* one to a second link from the same archive and confirm no second upload of either source.
A test that only inspects component state proves nothing here.

## Non-goals
- Per-document keys inside one container, or per-document deadlines within a link (the brainstorm's
  options 2–4). The bundle stays the unit of expiry.
- The TACo release path (H-52–H-55). This story uses the existing holder.
