# H-42 — The mobile tab bar still covers the last control on the page

## Story
- At 400px on `/import-review`, the primary action *"Fix the 3 flagged"* renders **behind** the
  fixed tab bar and cannot be tapped. H-37 was asked to fix this, measured it, reported it already
  correct, and the measurement was wrong.

## Context
Screenshot at 400x900 on 2026-09-12, after H-37 merged: the tab bar sits over the button, which is
partly visible beneath it. The bar is fixed; `main` carries `pb-28`; that clearance is not enough
for this page.

**Why the first attempt missed it.** H-37's evidence reads:

> playwright bounding-rect overlap check, tab bar vs lowest button, scrolled to bottom —
> `overlap=false` on all 4 pages at 400x900/700/2000 and 390x844, dev and production

A bounding-rect comparison is the wrong instrument, and it produced a confident false negative. It
can pick the wrong "lowest button", compare against a bar whose own rect excludes a blur or shadow
layer, or measure before a scroll settles. None of those show up as a failure — they show up as
green.

**Use the question the user actually asks:** *can I tap this?* Playwright answers it directly —
`elementFromPoint` at the control's centre, or an actual `click()` with no force, which fails when
something else intercepts the pointer. That cannot return a false negative for the reason above,
because it tests the thing itself rather than a proxy for it.

## What to build
- Give the content enough bottom clearance that the last interactive element on every mobile page is
  tappable: `/add`, `/import-review`, `/new`, `/shares`, and `/` once it has content. Fix it once in
  `components/chrome.tsx`, not per page.
- The bar is `$glass-raised` and translucent, so clearance must account for its full painted height,
  not just its layout box.
- **Assert tappability, not geometry.** For each mobile page, scroll to the bottom and assert the
  last control receives a real click. Record the red-then-green in `## Choices`.
