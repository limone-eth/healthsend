# H-41 — The sender layout is 672px wide; the canvas is 1176px

## Story
- `app/(sender)/layout.tsx` caps content at `max-w-2xl` — **672px**. Every desktop frame in
  `healthsend.pen` is 1440 wide with a 264px rail and a **1176px** content column. Sender screens
  are being built into 57% of their designed width.

## Context
Raised independently by two workers on 2026-09-12, both marking it `needs-user` because the layout
file was off-limits to them:

- **H-8** (*New share*): *"Collapsed the frame's two-column desktop layout to one column at every
  width — layout.tsx caps all sender content at max-w-2xl/672px, which cannot fit the frame's
  1080px two-column split."*
- **H-10** (*Your shares*): *"Content width is set by the existing shared layout (672px), not the
  frame's 1080px column."*

Both escalated correctly rather than editing a file they were told not to touch, and both built
fluid so widening costs nothing. The constraint came from the H-4 brief, which carried `max-w-2xl`
over from the original single-column scaffold without checking it against the frames.

**What it costs.** 2.3 *New share* is drawn as a scope accordion beside a fixed summary panel;
2.6 *Your shares* as a list beside its detail. At 672px neither can be two columns, so the screen
that `DESIGN.md` calls "the product" ships as a stack. This is not a styling nit — the summary panel
sitting *next to* the scope choices is the interaction.

## What to build
- Widen the `(sender)` content column to the canvas's 1176px, with the 264px rail beside it, so a
  1440px window matches the frame.
- Let each screen choose its own inner layout. The layout provides the column; it does not impose a
  single-column stack on everything inside it.
- Mobile is unchanged: one column, tab bar, the same breakpoints H-3 established.
- Re-check `/new` and `/shares` against `HMa4U` and `hCcwO` afterwards, and restore the two-column
  arrangement in each. Both pages were built fluid for exactly this, so it should be additive.
- `/add` and `/import-review` were built at the current width and will reflow — check them too.

Building them at 672px means rebuilding them later, which is the same mistake twice.
