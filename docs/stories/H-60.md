# H-60 — Sender screens drift from their frames, and one shows a name

## Findings (review 3)
- **R3-007 (high)** `app/(sender)/layout.tsx:99` — **a signed-in name still appears on every sender
  route.** This contradicts the settled decision that the product has no name to print — a passkey
  carries none. Remove it.
- **R3-006 (high)** `app/(sender)/new/page.tsx:264` — the send screen enters two-column mode 512 px too
  early. The frame's split is 640 + 400 at a 40 px gutter inside the 1080 measure.
- **R3-021 (medium)** `app/(sender)/new/page.tsx:277` — the summary panel is not sticky; the frame and
  `DESIGN.md` both say sticky.
- **R3-008 (medium)** `app/(sender)/page.tsx:115` — a grant count is presented as a people count. Two
  grants to one recipient read "2 people", and one reads "One person see part of it".
- **R3-020 (medium)** `app/(sender)/page.tsx:144` — mobile archive renders ~179 px desktop cards; frame
  `zsDfc` specifies five 62 px list rows.
- **R3-011 (medium)** `e2e/mobile-tab-bar-clearance.spec.ts:18` — four required mobile routes have no
  click test.

## What to build
Remove the name. Correct the breakpoint and stickiness to the frame. Count people, not grants, or say
"shares" — and fix the grammar. Mobile archive as list rows. A real unforced `click()` on each mobile
route; a rect comparison is not evidence (H-37).

## Non-goals
- Scope selection or the archive loader.
