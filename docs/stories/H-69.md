# H-69 — Make Chipotle the live key release for shares from the archive

## Story
- A share made from the archive keeps its second key half in Lit's Chipotle enclave instead of on our
  holder server, and the enclave hands it back only while the Arkiv grant is still live.

## Why
Operator decision, 2026-09-12: *"use Chipotle because it works today… Keep TACo built, but park that
code."* H-65 and H-67 built the Chipotle adapter against Lit's real API. Nothing uses it yet:
- `createSendFromArchive` and `createSend`, the only paths the UI calls, hand the held share to
  `/api/holder/share`.
- The v3 threshold path (`createThresholdSend`, and `openSend`'s `payload.v === 3` branch) is
  hardwired to `createTacoKeyReleaseProvider`.

The operator has an account, a `healthsend` group (id 1) with one wallet, and a usage key. Registering
the action CID is the operator's step and may not be done when this runs. Build it so the switch,
`NEXT_PUBLIC_CHIPOTLE_ENABLED`, is the only thing between this code and live.

**Say it plainly everywhere:** Chipotle is an enclave service run by Lit, a TEE-derived key. It is not
decentralised, not trustless, and not a threshold network.

## What to build
- **One provider-neutral factory** (e.g. `lib/key-release/index.ts`):
  - **Protecting:** returns the Chipotle provider when Chipotle is enabled and configured. TACo stays
    parked, so it is never chosen for new shares.
  - **Releasing:** chooses by the grant's own `payload.release.provider` descriptor, never by today's
    env. A share protected by one provider must always release through that same provider.
  - **Refusing:** a descriptor the build does not know fails closed, with a clear error.
  - `lib/sends.ts` depends on the factory, not on `createTacoKeyReleaseProvider`. Keep dependency
    injection so the offline proofs can pass a fake.
- **`openSend` v3 branch:** release through the factory. A `ChipotleUnavailableError` reads as
  `unavailable`, exactly as `TacoUnavailableError` does today. The one authoritative "expired" remains
  the head-boundary check.
- **`createSendFromArchive` with Chipotle enabled:**
  - Bind the grant to a pinned `expiresBlock` (`buildGrantBinding`; never a duration, see `CLAUDE.md`).
  - Protect the held share through the factory and write the v3 grant via `createThresholdGrant`.
  - Keep the owner/expiry mismatch refusal that `createThresholdSend` already has.
  - **No holder hand-off.**
  - With Chipotle disabled, today's holder path is unchanged. Prefer sharing code with
    `createThresholdSend` over a third copy.
- **The four-digit code (H-7)** is enforced by the holder: five tries, then lock. Chipotle has no such
  counter. So a share **with a code stays on the holder path** even when Chipotle is enabled, and only
  a code-less share goes through Chipotle. Record this under `## Choices` as provisional.
- **Ending a v3 share early:** there is no holder half to delete. Find what actually ends it:
  - The action checks the grant is live on Arkiv, so deleting the grant entity as its owner should
    make the enclave refuse. Implement that for v3 shares.
  - Prove the enclave refuses afterwards with a fake client offline.
  - If owner deletion isn't possible on Arkiv, say so and leave the End action off for v3 shares
    rather than showing one that does nothing.
- **Opens:** the access log lives in the holder, so v3 shares have none. Anywhere the UI states opens
  (Your shares, and H-18's "opened on" note), a v3 share must show nothing rather than "not opened".
- **`/api/holder` preflight:** a Chipotle send must not fail just because the holder is down.

## Evidence
- **Offline proofs, run red first** (dependency-injected like `scripts/archive-send-proof.mjs`):
  - an enabled archive send never calls `/api/holder/share` and writes `v: 3` with a Chipotle
    descriptor;
  - a TACo-descriptor grant still routes to TACo;
  - an unknown descriptor fails closed;
  - a coded share stays on the holder;
  - a disabled flag leaves today's behaviour byte-identical.
- **E2E:** the recipient opens a v3 Chipotle fixture through a mocked Chipotle endpoint.
- **Live:** `RUN_CHIPOTLE_LIVE_PROBE=1 pnpm verify:chipotle-adapter-live`, reporting the stage it
  reaches. Blocked at `single-action` because the action is not registered yet is an acceptable
  outcome; say so.
- `pnpm lint`, `pnpm build`, `pnpm exec tsc --noEmit`, `pnpm test` and every non-live `verify:*` lane
  pass.
