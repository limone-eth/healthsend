# H-73 — Sign in says "Continue with Passkey"

## Story
- The sign-in button names what actually happens: a passkey. Face ID is only one way to unlock one,
  and it doesn't exist on most computers or Android phones.

## Operator request, 2026-09-13
Screenshot of 1.2 Sign in: the button reads **"Continue with Face ID"**, set in a monospace face that
matches nothing else on the page. Instruction: *"this should be continue with Passkey, not Face ID."*

## Where it lives
- **The label is not in our JSX.** It is `buttonConfig.connectText` in `lib/swarm.ts` (`getSwarmClient`).
  The Swarm ID SDK paints the button **inside its iframe**, in `#swarm-id-connect`
  (`CONNECT_CONTAINER_ID`).
- **The comment above it says our stylesheet cannot reach the button.** Only `backgroundColor`,
  `color` and `borderRadius` are exposed today.
- **The lede and footnote** ("Use your face, your fingerprint or your screen lock…", "The same face or
  fingerprint reopens…") are in `components/sign-in-screen.tsx`. They correctly describe how a passkey
  is unlocked. Leave them unless they contradict the button.

## What to build
1. **Button text:** `connectText: "Continue with Passkey"`. Update the comment, which currently says
   "Verbatim from frames BsnX6 / GdIlc". The orchestrator is updating those pen frames to the same text.
2. **Font:**
   - Check the installed SDK's `buttonConfig` type (`node_modules/@snaha/swarm-id`) for any font or
     typography option, e.g. `fontFamily`, `fontWeight` or a style object.
   - If one exists, set it to the app's UI face as served in the page (read it from
     `app/layout.tsx` / `globals.css`). A font the iframe cannot load falls back, so choose a stack
     that degrades to the system UI font, never to monospace.
   - If none exists, don't hack around the iframe. Add a short `friction.md` entry: expected vs
     actual, the SDK version, and a suggestion (`buttonConfig.fontFamily`). Say so under `## Choices`.
3. **Tests:** any spec or proof that pins the old label (`grep -rn "Face ID" e2e scripts`) is updated.
   If no test reads `buttonConfig.connectText`, add a small proof that fails on "Face ID".

## Evidence
- A proof, run red first, that the configured connect text is "Continue with Passkey".
- Browser at 1440 and 400. The sign-in screen renders, and the button inside the Swarm ID iframe reads
  "Continue with Passkey". If a real-origin iframe can't load offline, capture what the stub shows and
  say so.
- `pnpm lint`, `pnpm build`, `pnpm exec tsc --noEmit`, `pnpm test`, every non-live `verify:*` lane pass.
