# H-1 — Design tokens and the primitive kit

## Story
- Every screen in `healthsend.pen` is drawn from one token map and nine components. The app ships
  neither, so no screen after this one can be built faithfully until it exists.

## Context
Depends on: nothing. **Blocks almost every other story.**

`DESIGN.md` frontmatter carries the complete set: 23 colours, 8 typographic roles, the space,
radius and elevation scales. `app/globals.css` today defines six ad-hoc variables and
`components/ui.tsx` is 63 lines of placeholder.

Land the tokens, then rebuild `components/ui.tsx` as the documented primitives. Their masters
are components in the pen file, so there is nothing to invent:

| Action | `D61Fd` | § Action |
| Chip | `X2HSj7` | § Share state chip |
| Field | `vG3Zj` | § Field |

Type is Switzer with a Figtree fallback; declare a real fallback stack rather than letting it
fall silently to system sans.

**No screen changes in this story.** It lands the kit plus a `/kitchen-sink` route rendering
every primitive in every state, which is what the operator reviews. Countdown is deliberately
not here — it is H-2.

## Reading the design

**`healthsend.pen` is the source. A screenshot of it is not.** Read the nodes with the
`mcp__pencil__execute` tool against `<repo>/healthsend.pen`:

```js
Print(JSON.stringify(Get("<a frame id named in this story>", {depth: 6}), null, 1))
```

- `Get(id, {depth: n})` returns exact geometry, fills, strokes, corner radii, gaps, padding, font
  family, size and weight — and the `$token` references **by name**. None of that survives a
  screenshot, and guessing it is how a build ends up approximately right and visibly off.
- Add `resolveInstances: true` to expand component instances; the ids that come back are
  `instanceId/childId` paths you can read further.
- `Get(id, (n, c) => Print(n.name, c.bounds.width, c.bounds.x))` gives resolved bounds in the
  parent's coordinate space. Use it to check alignment and spacing rather than measuring pixels by
  eye. `c.problems` flags anything clipped by its parent.
- **Copy every string verbatim from the `content` fields.** Re-typing copy from an image is how a
  claim that was deliberately corrected gets silently restored — that has already happened once in
  this project, which is why H-20 says so explicitly.
- `TakeScreenshot([id])` is for confirming your build matches after you have read the nodes. It is
  never the input.

**Read only.** Never call `Insert`, `Update`, `Copy`, `Replace`, `Delete`, `Move`, `SetVariables`
or `Generate` against the canvas, and never commit `healthsend.pen`. The pencil MCP server drives
the operator's live editor, not your worktree's copy of the file — a write from a worker lands in
their open document. The design is an input to this story and an output of none.

Node ids named in this story are stable and can be read directly. The frame is the contract; where
this story's prose and the frame disagree, read the frame and say so in `## Choices`.

**Routing:** this story needs a worker whose engine has the `pencil` MCP server. It is configured
globally on this machine, so a Claude worker in a worktree inherits it; an engine without it can
only see exported images and must not be given this story.


## Review log

## Choices

- **Chip height is 34px, not the 28px DESIGN.md's prose and frontmatter state.** The master
  (`X2HSj7`) and every real instance of the seven share-state chips on Sheet 0's "The life of a
  share" table (node `NgI3h`) are all 34px. Two stray instances elsewhere in the file are 28px and
  26px, but the master and the documentation table — the two authoritative sources — agree on
  34px, so that is what shipped. `DESIGN.md`'s "28px" line is stale.
- **Focus Card drops the master's photo-behind-gradient fill and background-blur stat strip.**
  `Vxyho` carries an image fill plus a blurred `glass-input` panel — both Omea-kit leftovers.
  `DESIGN.md`'s own "No photography" section overrides this explicitly for HealthSend: the flat
  `grad-focus` gradient replaces the photo everywhere, and the panel over it is flat
  (`panel-on-dark`, no blur) because there is no media behind it to blur. The built component
  follows the written rule, not the master's raw fill.
- **Tab Bar uses `glass-raised`, not the master's `glass-tabbar`.** `DESIGN.md` states plainly
  that `glass-tabbar` "has no callers in this product" and that `glass-raised` is the one glass
  tier HealthSend keeps, specifically for the mobile bottom bar. The master (`kGlX0`) still
  carries the parent kit's own token; the built component uses the one HealthSend actually ships.
- **Focus Card's headline uses the systemic Headline type role (28/600/-0.5) rather than the
  master's inline override (24/700/-0.5).** Every other primitive composes from the five documented
  type roles; keeping one component's headline off-scale would make the type system a set of
  exceptions rather than a scale.
