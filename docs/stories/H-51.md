# H-51 — An Arkiv v3 grant whose policy cannot be extended or substituted

## Story
- The release rule is only as good as the entity it points at. Make that entity impossible to
  swap, stretch, or read at a convenient past block.

## Context
Task 2 of the TACo PoC plan. Depends on H-50's binding shape.

Three traps the plan names, all of them cheap to get wrong:

- **`readonly` is not immutable.** The SDK's flag blocks content and attribute patches but still
  permits extension, transfer and deletion. A fixed-expiry product must cap the deadline in the
  release policy itself, not rely on the entity's current existence.
- **The condition must query current state, never `atBlock`.** A policy that reads a pinned
  historical block can be satisfied forever.
- **Client-supplied identifiers must not choose the entity.** Otherwise a caller substitutes a
  live grant for its expired one and the whole scheme collapses.

## What to build
`lib/arkiv.ts`: v3 payload parsing, a random `grant_id` attribute, **native `entity.owner` and
`entity.expiresAt` as the authoritative fields** rather than the duplicated `sender` and
`expires_block` custom attributes the current adapter trusts, and exact-expiry creation.

v1 and v2 payloads must keep parsing. Existing links stay readable — this is additive.

## Two things in `CLAUDE.md` will bite
Arkiv attribute names are lowercase and the engine rejects `A`–`Z` **on-chain**, so a camelCase
attribute costs a reverted transaction. Query predicates must carry the same tagged type as the
write — a mismatch silently matches nothing rather than erroring.

## Evidence
Offline, against a fake Arkiv: a substituted entity is refused, an extended expiry does not widen
the policy, an `atBlock` read is rejected, and v1/v2 payloads still parse. `verify:crypto`,
`verify:revoke` and the existing recipient specs stay green.

## Non-goals
- TACo itself (H-52) and the send path (H-53).
