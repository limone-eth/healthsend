# H-43 — The rail shows a name the product cannot know

## Story
- The sender rail ends with an avatar and a personal name. A Swarm ID is a passkey — there is no
  first name, no last name, no profile, and nothing to populate it from. The built app renders
  whatever the Swarm ID iframe happens to expose; the canvas rendered *"Giulia"*.

## Context
Raised by the operator on 2026-09-12. The canvas has been corrected in the same pass: all ten
desktop frames' **Account Row** now shows a `sign-out` glyph and the label **Sign out**, replacing
the `user-circle` and the name.

That is the right replacement rather than simply a deletion. The rail's foot is where a person
looks for their account, and signing out is a real control the product needs and currently hides —
the old `app/page.tsx` had one, and the H-4 route split left it in the layout without a home in the
rail.

## What to build
- Replace the rail's account row with **Sign out**, matching the canvas: `sign-out` Phosphor glyph
  at 20px `$muted`, label 14px `$secondary`, 44px row, 14px horizontal padding.
- Wire it to the existing sign-out path in `app/(sender)/layout.tsx` — it already has one; this
  gives it the place the design puts it.
- Do not display any name, anywhere, on any sender surface.
- Mobile is unaffected: the tab bar has three items and no account row, which is already correct.

## The related problem, which is not this story
Fifteen strings across the **recipient** frames say things like *"Giulia shared health data with
you"*. The recipient page cannot know that either — the sender has no name to send.

That one is a product decision rather than a deletion, so it is deliberately not folded in here:

- add an optional *"from"* the sender types at compose time, and show it only when set; or
- drop sender attribution entirely and rely on context, which `DESIGN.md` § 2.5 already assumes —
  *"Send it to Elena however you normally talk to her"* — since the link travels over a channel
  where the recipient already knows who is writing.

Worth deciding before H-5 rebuilds the recipient view, because attribution is the first thing on
that screen.
