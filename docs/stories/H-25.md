# H-25 — An offline browser lane for the recipient surface

## Story
- Three of the recipient's five states cannot be tested without a real Swarm upload, a funded Arkiv
  key and a live holder. So they are not tested — including the two the product's honesty rests on.

## Context
Depends on: nothing. Blocks nothing, and makes H-5, H-6 and H-7 verifiable instead of eyeballed.

`e2e/recipient.spec.ts` exists and is good as far as it goes: it asserts a guest arrives with no
cookie and that an unknown grant reads as expired. But the happy path is gated behind a manually
pasted `SHARE_URL`, so in practice nobody runs it, and **`unavailable` has no test at all**.

That is the wrong gap to have. `expired` and `unavailable` are the two states that must never be
confused — one is the sender's window closing, the other is our infrastructure failing, and
`README.md` § The cost, stated plainly is explicit that showing the wrong one is a lie about the
reader's access. A distinction that important should not rest on having remembered to look.

The fix is route interception, not more infrastructure. Playwright can stub `/api/holder/unlock`
and the Swarm gateway inside the browser, which makes every recipient state reachable offline, in
Chromium, with no credentials and no network.

This also gives the repository its first real `pnpm test`: one command that runs the crypto
round-trip and the browser lane together, so "unit and browser, both green" is a thing a person can
check in one line rather than a claim in a report.
