# H-47 — Two more claims this product cannot honour

## Story
- The landing page still promises deletion at the expiry date, and the README still promises that
  compromising us entirely reaches nothing.

## Context
From review 2. This is the **fifth and sixth** false claim found in this product; the previous
four were a revoked send saying "Nobody revoked this", a deletion time ignoring the grace period,
a demo notice calling a bearer link recipient-only, and a notice implying de-identification runs.

**R2-010 — high — the landing page promises deletion at the date.** `lib/holder-store.ts:66`
defines `TTL_GRACE_SECONDS = 3600` and lines 149-160 add it to holder retention, so the held half
can outlive the stated moment by an hour. H-35 corrected this exact sentence on the sender screen
and left the landing copy carrying it. `app/landing/page.tsx:265`.

**R2-009 — high — the README claims a full compromise reaches nothing.** Browser-side encryption
bounds what a compromise of *stored data* reaches. It cannot protect plaintext from a compromised
deployment that serves the JavaScript: our code reads the file before encrypting it
(`lib/sends.ts:78-103`) and serves the recipient's decryption code. The absolute claim is at
`README.md:258-268`.

**R2-011 — medium — the landing page has no working mobile entry action.** `app/landing/page.tsx:130`.

**R2-023 — low — the README describes a checkout three stories old.** It still names `app/page.tsx`
as the upload and share-list route (split into `/new` and `/shares` by H-4), and says revoke,
access logs and unlabelled detection are absent, when all three exist. `README.md:450-469`,
`546-549`, `605-610`.

## What to build
Say the true thing in each case, and say it as specifically as the false version was confident.

- The landing copy: the held half is deleted, and the window between the stated date and the
  deletion is bounded and known. State the bound rather than removing the claim — a vaguer
  sentence is not more honest, only less checkable.
- The README: name what browser encryption does and does not cover. A compromised deployment that
  serves the page can read plaintext, and no amount of client-side crypto changes that. The
  document already has an honest register elsewhere — the holder trust cost section — so match it.
- The landing page needs a working entry action at phone width.
- Bring the stale README sections up to the current checkout.

## Also — one screen that speaks two ways
`app/(sender)/new/page.tsx`'s Link ready lede reads "however you normally talk to **them**", and
the summary row beside it reads "What **she** sees about you", with a footnote "**she** loses
access straight away". The chip vocabulary was de-gendered on 2026-09-12 ("On their device") and
these were missed. Fix the build **and** the frames — `A4L3dx`, `eonlR`, `x9IoK`, `kpB2B` at
minimum — so the canvas does not re-introduce them. Read the canvas for the rest of the sender
flow while you are there and list what you changed.
