# H-58 — Three checks that do not check

## Findings (review 3)
- **R3-003 (high)** `lib/sends.ts:93` — the holder preflight does not contact Redis. H-39 exists to
  stop a grant being written when the holder is unusable; a preflight that never reaches the store
  passes while Redis is down, so the grant is written anyway.
- **R3-005 (high)** `e2e/recipient.spec.ts:87` — the recipient tests accept the wrong holder
  authentication key. H-34 tightened the stubs; this one still answers regardless.
- **R3-010 (medium)** `e2e/helpers/network.ts:212` — a same-origin `sendBeacon` bypasses the offline
  guard, so the "never reaches an unstubbed route" claim has a hole.

## What to build
A preflight that performs a real round trip to the store. A stub that refuses a wrong auth key, with a
test that fails if it stops refusing. A guard that catches beacons. Each demonstrated red first —
break the production line, watch it fail, restore.

## Non-goals
- The TACo send path. **H-53 will also edit `lib/sends.ts`** — keep the preflight change contained.
