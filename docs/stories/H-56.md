# H-56 — "Added to archive" adds nothing

## Story
- `/import-review`'s confirm button says the record was added and ready to share. It sets a
  document id in React state. Refresh and it is gone; New share cannot see it.

## Context
From the screens audit, two criticals in one action.

**F-03.** *"Looks right — add to archive"* only pushes an id into local component state, and then
the success message reads *"Added to archive — ready to include in a share."* Both halves of that
sentence are false: nothing was added, and nothing can include it.

**F-02.** The same screen says *"The file itself stays in your archive so you can come back and
compare."* Nothing stores the file.

**Why this is now a small story rather than a large one.** H-44 landed `lib/archive-store.ts`,
`lib/archive-manifest.ts` and `lib/archive-input.ts` — a real encrypted archive on Swarm, keyed by
identity, with `/add` already writing into it and `app/(sender)/page.tsx` reading it back. The
import-review path is the one entry point that was never connected to it.

## What to build
- The confirm action writes through H-44's archive store, the same way `/add` does.
- The success message may only claim what happened. If a write fails, say so.
- **Decide what "the file itself stays" means, and make the copy match.** H-44 stores parsed
  *records*, not the original document. Either keep the source file alongside them, or change the
  sentence. Do not leave it promising the one thing neither option currently does. Say which you
  chose in `## Choices`.

## Evidence
Reload, and cross-route. Confirm an import, refresh the browser, and find the record in *Your
archive*. Then open *New share* and find it selectable. A test that only inspects component state
proves exactly the bug this story exists to fix.
